要疯掉了


hexo+github双分支+cloudfare page+vercel部署qexo的现在问题是qexo发文后hexo博客不显示

这个问题**在你这个架构下非常典型**，结论先给出一句话，然后我一步一步帮你对照排查 👇

> **Qexo 发文成功，但 Hexo 博客不显示，99% 是因为：
> Qexo 写进了“Hexo 源码分支”，但 Cloudflare Pages 实际部署的是“生成后的静态分支”，中间没有触发 `hexo generate`。**

你现在的架构是 👇（我按你前面的聊天还原）

---

## 一、你现在的整体架构（关键）

### 1️⃣ GitHub 仓库（双分支）


| 分支                | 内容                                                           |
| ------------------- | -------------------------------------------------------------- |
| **main / source**   | Hexo 源码（`source/`、`_config.yml`）← Qexo 操作的            |
| **gh-pages / dist** | `hexo g`生成的静态文件（`index.html`）← Cloudflare Pages 用的 |

✔️ 这是**正确架构**

---

### 2️⃣ 各服务在干什么


| 服务                     | 实际作用                               |
| ------------------------ | -------------------------------------- |
| **Qexo（Vercel）**       | 👉 只会**改 Hexo 源码**（source 分支） |
| **Hexo**                 | 👉 需要你执行`hexo g`才会生成页面      |
| **Cloudflare Pages**     | 👉**只部署静态文件分支**               |
| **GitHub Pages（可选）** | 👉 同样只看 gh-pages                   |

---

## 三、你可以用 3 秒自查（非常重要）

### ① 看 GitHub 分支提交记录

👉 打开仓库：

* **source / main 分支**
  * 是否看到你刚刚 Qexo 发布的 `.md` 文件？
    ✔️ 有 → Qexo 没问题
* **gh-pages 分支**
  * 提交时间有没有更新？
    ❌ 没有 → 问题确认

## 四、解决方案（按推荐顺序）

---

## ✅ 方案一（最稳妥，强烈推荐）：GitHub Actions 自动生成

### 原理一句话

> **Qexo → 提交源码 → GitHub Actions 自动 hexo g → 推送 gh-pages → Cloudflare 自动更新**

---

### 1️⃣ Cloudflare Pages 设置（先确认）

* **Build branch**：`gh-pages`
* **Build command**：❌ 留空
* **Output directory**：❌ 留空

👉 Cloudflare 只当“静态托管”

---
